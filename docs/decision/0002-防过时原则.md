# ADR 0002：防过时原则（架构稳定，配方可换）

- 状态：已接受
- 日期：2026-11-25

## 背景

知识库/RAG 领域每年都在换“最佳实践”：框架、模型、切分参数都在变。担心投入半年后整体作废。

## 结论

用“稳定层 + 易变层”分离的方式抵抗过时，不做单点押注。

### 稳定层（十年不变，必须自持）

1. **原文 + 关系库是源真相**；向量库、图库都是可从零重建的派生索引。
2. **人工黄金集**：问题 + 标准答案 + 应命中证据。模型换代不影响评测方法。
3. **数据契约**：chunk 元数据结构（来源/章节路径/时间/权限）、三元组必带证据句。
4. **薄接口**：`检索(问题) -> 证据[]`、`抽取(文本) -> 三元组[]`。框架只是实现。

### 易变层（12 个月内会变，必须可替换）

- 编排框架（LlamaIndex / LangChain / 各 Agent SDK）
- embedding 与 rerank 的具体型号
- chunk 大小、top-k 等经验参数
- 抽取 prompt 与本体细则

## 硬规则

- **换掉某个库，业务代码改动不得超过 20%**。超了说明封装错了，先重构。
- 业务逻辑不得写进第三方框架的 DSL / 工作流图里。
- 一体化平台（RAGFlow / Dify / FastGPT）只用于原型对照，不进产品路径。
- 任何检索/生成组件的替换，必须能跑通同一套黄金集回归。

## 影响

- 前期多花一点时间写接口与测试，换来后续换模型不用推倒重来。
- 选型讨论的焦点从“哪个框架最好”转为“哪些接口要固定”。
