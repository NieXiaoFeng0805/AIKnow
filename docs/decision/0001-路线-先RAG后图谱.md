# ADR 0001：知识库总体路线（先 RAG，按需上图）

- 状态：已接受
- 日期：2026-11-25

## 背景

需要一套个人/团队知识库，覆盖文档问答，未来可能涉及关系型推理。约束是人力有限、要尽快产出可用结果。

## 选项

1. 直接建知识图谱（本体 + 抽取 + 图库）
2. 先做 RAG，关系诉求明确后再对子域上图
3. 只做结构化数据库 + Text2SQL

## 结论

选 2。三层递进：

| 层 | 解决什么 | 何时启用 |
|---|---|---|
| ① 文档库 + RAG | 答案在一两段原文里 | 立刻 |
| ② 结构化知识库 | 精确字段、数值、清单 | 出现统计类问题时 |
| ③ 知识图谱 | 多跳关系、路径、传导 | badcase 明确显示缺关系时，且只做一个子域 |

## 依据

- 多数问答需求能由“检索 + 引用”满足；图的成本主要在抽取与治理，不在存储。
- 图谱的价值是把关系当索引做多跳召回，不是替代全文检索。

## 影响

- 源真相固定为“原文 + PostgreSQL”，向量库与图库都是可重建派生索引。
- 上线前必须有人工黄金集，否则无法判断迭代方向。
- 图谱 schema 起步上限：实体 ≤ 10 类、关系 ≤ 15 类，三元组必须带证据句与出处。
