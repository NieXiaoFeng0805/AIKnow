# ADR 0003：用分区替代全局问答，放弃社区摘要层

- 状态：已接受
- 日期：2026-11-27
- 关联：设计 v3（docs/design-v3.md）

## 背景

v2 方案规划了三层图（lexical / entity / community），其中 community 层只为回答"全局问题"服务——比如"这批资料总体讲了什么"。主人明确：不需要全局问答，改为按内容分生活/工作/学习三个区。

## 选项

1. 保留 community 层，同时上分区（最全，最贵）
2. 砍掉 community 与 global 查询，用"分区 + 区内检索"满足需求
3. 砍掉分区，只做全局（与使用习惯冲突，排除）

## 结论

选 2。

## 依据

- 全局问答的真实需求是"跨主题综述"，而分区本身就提供了粗粒度的综述单位（每区一份月度摘要即可，成本约为社区层的 5%）。
- 社区检测与摘要约占索引成本的 20–30%，且需要全库重算，与"增量更新"目标冲突。
- 分区同时带来一个正收益：**串区污染被结构性杜绝**，检索边界清晰。

## 影响

- 数据模型所有表加 `zone_id`；实体按区隔离命名空间。
- 检索默认硬过滤本区，跨区只能显式开启。
- 评测增加"串区检测"指标，去掉"跨主题综合"指标。
- 若未来出现"必须跨区才能回答"的真实问题，用 `links` 表补连接，不恢复社区层。
